# 故障排查

先在服务器上执行：

```bash
sudo vpnkit status
sudo vpnkit doctor
sudo vpnkit urls
```

`urls` 输出包含私密订阅链接和可选监控登录信息，请勿原样发到公开 Issue。`doctor` 检查本机服务、配置、证书、监听端口和续期定时器，不会测试实际代理流量、服务器出口、DNS 或客户端网络。客户端超时既可能由服务器引起，也可能由客户端到服务器之间的网络引起；本机检查不能代替客户端网络测试。

## 安装前检查

本项目支持 Ubuntu 22.04 / 24.04、Debian 12 / 13，amd64 / arm64 和 systemd。需要独立公网 IPv4；NAT 主机必须有对应端口映射，否则不适用。其他操作系统、IPv6-only 和无 systemd 的容器不受支持。

如果提示没有 `curl`，请先通过发行版包管理器安装 `curl` 和 `ca-certificates`。如果已是 root 但没有 `sudo`，从安装命令中去掉 `sudo` 即可。

### 端口被占用或已有部署

安装器不会接管已有 VPN 或网站。可检查监听状态：

```bash
sudo ss -lntp
```

核对 TCP 80、443、8443，以及启用监控时的 8444。若由现有网站、VPN 或其他服务占用，请先确认其用途；使用一台干净 VPS 通常比在生产网站上改动端口更直接。不要为了绕过检查而随意停止未知服务。

## FlClash 和 Shadowrocket 都显示 timeout

1. 运行 `vpnkit status` 和 `vpnkit doctor`，确认服务正在运行。
2. 核对客户端订阅内容中的服务器 IP，尤其是云平台刚换过 IP 的情况。导入旧订阅地址不会自动发现新 IP。
3. 检查云平台安全组和主机防火墙是否同时允许 TCP 443。检查实例是否运行、账户是否欠费、流量额度是否耗尽。
4. 从另一个网络测试，例如手机蜂窝网络。若同一客户端在别的网络正常，问题可能在当前网络的路由或访问限制。
5. 检查服务器能否访问设定的 REALITY 握手目标，以及系统时间是否正确。默认目标是 `dl.google.com`。

如果从当前网络连接服务器的 SSH、订阅和 VPN 端口都超时，而从另一个网络正常，不应先重置密码或反复重装。确认云平台防火墙设置后，再检查线路或 IP 可达性。安装器无法解除运营商对 IP 的阻断。

## 能连接节点，但无法上网

先确认客户端已启用该配置，并选择了对应节点。运行 `vpnkit doctor` 排除本机服务、配置或证书错误，再分别检查服务器出口网络、DNS、系统时间和握手目标可达性。

若只有某个网站不可用，请比较其他网站；单一网站的限制不一定意味着节点本身故障。不要关闭 TLS 证书校验作为通用修复办法。

## 订阅 URL 下载失败

- **连接超时**：检查 TCP 8443 的云安全组和本机防火墙；它与 VPN 使用的 TCP 443 是两个端口。
- **404**：从 `sudo vpnkit urls` 重新复制完整 URL，检查是否截断、带入空格或仍使用旧 IP。
- **证书错误 / 证书过期**：检查系统时间和证书续期状态。TCP 80 必须可从公网访问，以便自动续期；不要因为初次安装成功就关闭该端口。
- **网页能访问，但客户端导入失败**：确认选择了正确客户端对应的 URL，且客户端版本支持 VLESS + REALITY + Vision。FlClash 和 Shadowrocket 使用不同订阅格式。

VPN 流量使用 REALITY；HTTPS 订阅证书用于下载订阅和访问监控。证书错误可能影响更新订阅，但不能单凭这一点判断已有节点连接一定失败。

## IP 证书申请或自动续期失败

检查以下条件：

1. `--server-ip`（如有指定）是本机实际公网 IPv4，不是私网地址、旧 IP 或文档示例地址。
2. 公网能访问该 IP 的 TCP 80，且云安全组、主机防火墙、端口转发均正确。
3. 服务器能够连接 Let's Encrypt，系统时间正常。
4. TCP 80 没有被其他 Web 服务或控制面板占用。

不要短时间内反复申请证书；遇到 CA 限额错误，应按返回信息等待恢复。修复可达性后再重试相应命令。IP 证书有效期较短，持续正常的自动续期很重要。

## 更换公网 IP 后

这个工具不操作云平台换 IP。先在云平台完成更换，再运行：

```bash
sudo vpnkit update-ip --accept-acme-tos
sudo vpnkit urls
```

如果自动检测结果不对：

```bash
sudo vpnkit update-ip --accept-acme-tos --server-ip 203.0.113.10
```

将示例地址 `203.0.113.10` 替换为实际新 IP。执行后，在 FlClash 和 Shadowrocket 中替换订阅 URL 并更新订阅，监控书签也要使用新地址。仅点击旧订阅的“更新”无法修复已失效的旧 IP。

## 监控登录或统计异常

使用 `sudo vpnkit urls` 或 root 读取 `/root/vpnkit-access.txt` 获取监控地址和独立登录密码。监控账号不是 Linux 系统账号；不要填写 SSH 密码。

- 未提供正确认证信息时返回 `401` 是正常的访问保护。
- 监控入口使用 TCP 8444；需在云安全组放行该端口。
- 修改设置、关闭连接等操作不在只读监控权限内。
- “活跃来源 IP 数”为 0 可能只是当前没有活动流量。让客户端通过节点访问一个网站后再观察。
- 同一局域网下的设备可能共享来源 IP；不要把 IP 数或连接数直接解释为人数。

## 提交问题

请提供发行版版本、CPU 架构、使用的发布版本、执行的命令（删除私密参数）、错误信息以及经过检查和脱敏的诊断结果。不要公开完整订阅 URL、UUID、REALITY 私钥、监控密码、SSH 私钥或 `/etc/vpnkit/state.json`。
